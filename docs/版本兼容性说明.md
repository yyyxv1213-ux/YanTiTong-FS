## 3. 关键选型与兼容性说明

### 3.1 MySQL 5.7.26 与规范建议 8.x 的差异说明

任务规范建议 MySQL 8.x，本项目开发/联调环境实际使用 **MySQL 5.7.26**，原因与兼容性论证如下：

1. **环境约束**：本机 phpStudy 集成环境自带的 MySQL 即为 5.7.26，为与联调环境保持一致而采用；
2. **驱动向下兼容**：`mysql-connector-j 8.0.33` 为 Oracle 官方驱动，官方向下兼容 MySQL 5.7 服务端；连接串已按 5.7 习惯配置 `useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true`，规避 8.x 驱动连接 5.7 时的 SSL 与公钥检索问题；
3. **DDL 双向兼容**：V1__init.sql 未使用任何 MySQL 8.0 专属语法（如窗口函数、`utf8mb4_0900_ai_ci` 排序规则、CTE、`ON UPDATE CURRENT_TIMESTAMP` 之外的特性均不依赖版本），可在 5.7 与 8.x 上原样执行；
4. **生产可无缝升级**：切换至 MySQL 8.x 仅需更改服务端与连接账号，应用代码、DDL、驱动均无需修改。

### 3.2 Spring Boot 2.7.18 与 3.x 的差异说明

规范建议 Spring Boot 2.7.x 或 3.x，本项目选择 **2.7.18**：

- 本机 JDK 为 **Amazon Corretto 1.8（Java 8）**；Spring Boot 3.x 基线要求 **JDK 17**，在 JDK 8 下无法编译运行；
- **2.7.x 是支持 JDK 8 的最后一个大版本线**，2.7.18 为其最终维护版本，安全补丁覆盖完整；
- Spring Security **5.7** 随 Boot 2.7 同源配套托管，JWT 过滤器、`@PreAuthorize` 方法级鉴权、BCrypt 密码编码均在该组合下验证通过，无版本冲突。

### 3.3 Flyway 固定 7.15.0 的原因

- **Flyway 8.5+ 社区版不再支持 MySQL 5.7**（5.7 支持被移入企业版 Teams Edition）；
- 7.15.0 是支持 MySQL 5.7 的最后一批社区版之一，与当前数据库版本匹配；
- Boot 2.7.18 默认托管的 Flyway 为 8.5.x，故 pom.xml 通过 `<flyway.version>7.15.0</flyway.version>` **覆盖父工程托管版本**，保证 `spring.flyway` 自动配置正常工作（application-dev.yml：`enabled=true`、`locations=classpath:db/migration`、`baseline-on-migrate=true`）。

### 3.4 测试库 H2 固定 1.4.200 的原因

- Spring Boot 2.7 默认管理 H2 **2.1.x**；
- 但 **Flyway 7.15 的版本探测 SQL 与 H2 2.x 不兼容**——H2 2.x 移除了 Flyway 探测所用的 `INFORMATION_SCHEMA.SETTINGS`，启动即报错；
- 故测试期将 H2 降级固定为 **1.4.200**（MySQL 兼容模式），仅在 `test` scope 生效，不影响生产使用 MySQL。

### 3.5 jjwt 0.9.1 与 jaxb-api 2.3.1 的配套说明

- jjwt 0.9.1 的签发/解析链路依赖 JAXB（`javax.xml.bind`）；
- **JDK 9+ 将 JAXB 从 JDK 中移除**，为保证在更高版本 JDK 上也能运行（尽管本项目基线为 JDK 8），pom.xml 显式引入 `javax.xml.bind:jaxb-api:2.3.1`，避免 `ClassNotFoundException: javax.xml.bind.DatatypeConverter`。

### 3.6 springdoc-openapi-ui 1.7.0 的适配说明

- springdoc-openapi **1.7.x** 适配 Spring Boot 2.7（基于 javax.* 命名空间）；
- Spring Boot 3.x 需升级至 springdoc **2.x**（jakarta.* 命名空间）；本项目为 Boot 2.7，故锁定 1.7.0，与 Knife4j 增强 UI 兼容。

### 3.7 MyBatis-Plus 3.5.5 的适配说明

- 使用官方 `mybatis-plus-boot-starter`（非 `mybatis-plus-spring-boot3-starter`），适配 Spring Boot 2.7；
- 全局配置与框架能力对应：`map-underscore-to-camel-case` 下划线转驼峰、`logic-delete-field: deleted` 逻辑删除（1 已删 / 0 正常）、`@Version` 乐观锁，均与数据库设计文档中 sys_user、question 表的设计一致。

### 3.8 单机内存实现的可替换性声明（限流与考试组卷会话）

- 接口限流切面（`RateLimitAspect`）、考试组卷会话（`ExamService`）及 JWT 注销黑名单（`TokenBlacklist`）当前均为**单机内存实现**（`ConcurrentHashMap`），application.yml 中已注释说明："接口限流配置（内存实现，生产可替换 Redis 分布式限流）"；
- 单机部署下功能正确；**集群/多实例部署时应替换为 Redis 分布式实现**（限流令牌桶、考试会话、令牌黑名单统一入 Redis）；
- 限流通过 AOP 切面隔离、考试会话通过 Service 内部封装隔离，替换时**业务代码零改动**，仅需替换切面/存储实现。

## 4. Maven properties 版本锁定说明

pom.xml 使用 `<properties>` 集中管理全部第三方依赖版本，保证构建一致性与可审计性：

```xml
<properties>
    <java.version>1.8</java.version>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
    <!-- 依赖版本集中锁定，保证构建一致性 -->
    <mybatis-plus.version>3.5.5</mybatis-plus.version>
    <mysql.version>8.0.33</mysql.version>
    <jjwt.version>0.9.1</jjwt.version>
    <springdoc.version>1.7.0</springdoc.version>
    <flyway.version>7.15.0</flyway.version>
    <!-- H2 固定 1.4.200：Flyway 7.15 不兼容 H2 2.x（版本探测 SQL 已移除），仅测试期使用 -->
    <h2.version>1.4.200</h2.version>
</properties>
```

- 所有版本号**单点定义、全 POM 引用**，升级时只需改一处，杜绝同一依赖多处版本不一致；
- `flyway.version`、`h2.version` 显式覆盖 Spring Boot 2.7 父工程托管版本，解决第 3.3、3.4 节所述兼容性冲突；
- 其余 Spring 生态依赖交由 spring-boot-starter-parent 2.7.18 统一管理，避免手工指定导致的"依赖地狱"。
