## 1. 产品定位与背景

研题通是我给自己备考 408 做的刷题工具：市面上现成的题库软件要么题目质量参差、要么广告和会员体系太重，我更想要一个题目可控、数据在自己手里的轻量系统。它定位为「自建题库 + 在线刷题」的内部使用系统，单机或局域网部署即可运行，不追求多租户和商业化能力。

核心思路有三条：

1. **刷题闭环优先**：抽题、判分、错题归集、按科统计，这条链路做扎实比堆功能重要；
2. **模拟考试还原考场约束**：限时组卷、防重放交卷、超时成绩作废，避免「边看解析边答题」的假努力；
3. **题库大类可扩展**：408 之外还要考软考和等级考试，架构上让新增考试类别只改数据不改代码。

## 2. 用户与角色

| 角色 | 编码 | 说明 |
|------|------|------|
| 学员 | STUDENT | 日常使用者：刷题、考试、错题、统计、计划 |
| 管理员 | ADMIN | 题库与账号的维护者：题目/分类/用户管理 |

未登录游客除题库列表等公开元数据外不可访问任何业务接口；RBAC 在后端 `@PreAuthorize` 强制，前端菜单仅做展示层隐藏。

## 3. 功能需求

### 3.1 登录认证（P0）

- 用户名 + 密码登录；邮箱验证码登录（6 位数字码，5 分钟有效，1 分钟内同邮箱不可重复发送）
- 双 Token：accessToken 短效 + refreshToken 换新，前端无感刷新；注销/改密后旧 accessToken 立即失效（黑名单）
- 每次签发的 Token 携带唯一 jti，杜绝同秒签发重复 Token
- 登录/注册/验证码接口按 IP 限流，超限返回 42900

### 3.2 题库大类（P1）

- 已上线题库列表公开可查（`/common/banks`），含科目定义 JSON
- 学员端顶部下拉切换，选择本地持久化；刷题、组卷、统计全部按题库隔离
- 非法题库编码、未上线题库、科目不属于该题库均拒绝并给出明确错误

### 3.3 刷题训练（P0）

- 筛选维度：科目、章节、题型、难度、模式（顺序 sequence / 随机 random / 错题 wrong），单次最多 50 题
- 下发的题目**不含答案与解析**，提交后即时判分并返回答案解析
- 判分规则：作答下标集合与答案集合完全一致判对（多选不限顺序，空作答判错）
- 作答记录与错题本联动：答错自动入错题本，答对且未掌握的题目标记已掌握

### 3.4 模拟考试（P0）

- 组卷：在当前题库内随机抽题，可限定科目，题量 5-100、时长 5-180 分钟
- 交卷带 examKey 一次性校验（防重放），超时（时长 + 5 分钟宽限）成绩作废
- 交卷后即时出分，保存考试记录与逐题明细
- 成绩报告仅本人可查（越权返回 40300），含题面、答案、解析与本人作答对比
- 考试历史分页展示，含得分、用时

### 3.5 错题本（P1）

- 按最近错误时间倒序列出未掌握错题，附错误次数
- 支持在线重做、手动标记已掌握（标记后从错题列表移除，记录保留）

### 3.6 学习统计与计划（P1）

- 总览：今日题数、累计题数、正确率、每日目标、距考试倒计时
- 分科统计：按题库定义的科目固定返回（无数据补零），保证图表横轴稳定
- 趋势：近 14 天每日题数与答对数，断档日期补零
- 学习计划：每日目标题数、考试日期（默认 2026-12-19，即 2027 届初试），每用户一条

### 3.7 个人中心（P1）

- 资料查看与真实姓名修改
- 修改密码需校验原密码，成功后当前 accessToken 加入黑名单强制重新登录

### 3.8 管理端（P0）

- 题目管理：按题库+科目筛选，分页查询（关键字/分类/题型/难度），新增/编辑/删除题目，选项与答案以下标 JSON 存储
- 分类管理：按题库维护章节分类，被题目引用的分类禁止删除
- 用户管理：分页查询、新增、编辑、启用/禁用、重置密码、分配角色、删除

### 3.9 明确不做（当前版本）

- 移动端响应式（已知短板，v1.1 评估）
- 富文本服务端过滤（当前依赖录入端自觉，见测试报告 DEF-05）
- 分布式部署（组卷会话为单机内存实现，见 ExamService 内 TODO）

## 4. 非功能需求

| 维度 | 要求 | 实测（详见《测试报告》） |
|------|------|--------------------------|
| 响应时间 | 常规接口 p95 < 200ms | 全部接口 p95 < 100ms |
| 并发 | 50 并发无错误、无超时 | RPS 峰值 1650，错误率 0% |
| 安全 | 参数化查询防注入、JWT 无状态、RBAC、限流 | 均已验证，2 个 P1 缺陷修复后复测通过 |
| 可测试 | 后端/前端/API 三层自动化 | 63 + 14 + 64 例全绿 |
