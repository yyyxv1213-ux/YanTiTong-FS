# 研题通·考研408刷题训练系统 — 部署文档

## 1. 开发环境启动

> 详细说明见 [README.md](./README.md)，此处为简版。

```powershell
# 1) 建库
#    CREATE DATABASE ytt_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

# 2) 后端（需 JDK 8，配置 JAVA_HOME；首次启动自动建表+种子数据+内置账号）
cd ytt-server
.\mvnw.cmd spring-boot:run        # 端口 8080，context-path /api，默认 dev profile

# 3) 前端（需 Node 16+）
cd ytt-web
npm install
npm run dev                       # 端口 5173，/api 代理至 8080
```

## 2. 生产构建

### 2.1 后端打包

```powershell
cd ytt-server
.\mvnw.cmd clean package
```

产物为 `target/ytt-server.jar`（`finalName` 已固定为 `ytt-server`）。启动方式：

```powershell
# Windows 示例（生产环境务必设置环境变量，见第 4 节）
java -jar target/ytt-server.jar --spring.profiles.active=prod
```

```bash
# Linux 示例
JWT_SECRET='your-strong-secret' \
DB_HOST=127.0.0.1 DB_PORT=3306 DB_NAME=ytt_db \
DB_USER=ytt DB_PASSWORD='your-db-password' \
MAIL_HOST=smtp.qq.com MAIL_PORT=465 \
MAIL_USERNAME='your-mailbox@qq.com' MAIL_PASSWORD='your-smtp-auth-code' \
java -jar ytt-server.jar --spring.profiles.active=prod
```

### 2.2 前端打包

```powershell
cd ytt-web
npm run build
```

产物为 `dist/` 目录（静态文件），交由 Nginx 托管即可。

## 3. 配置文件与环境说明

后端配置文件位于 `ytt-server/src/main/resources/`：

| 文件 | 说明 |
| --- | --- |
| `application.yml` | 公共配置：端口 8080、context-path `/api`、默认激活 `dev`、MyBatis-Plus（逻辑删除 `deleted`）、JWT（secret/access-expire 7200 秒/refresh-expire 604800 秒/header `Authorization`/前缀 `Bearer `）、接口限流（登录 5 次/分钟、默认 120 次/分钟）、Jackson 日期格式与时区 GMT+8、上传大小限制（单文件 5MB/请求 10MB） |
| `application-dev.yml` | 开发环境：数据源 `jdbc:mysql://localhost:3306/ytt_db`（root/root，HikariCP 最大连接数 20）、Flyway 开启、`com.ytt` 日志 debug；内置 QQ 邮箱 SMTP 配置（`smtp.qq.com:465`，SSL）用于联调邮箱验证码 |
| `application-prod.yml` | 生产环境（已提供）：数据源、JWT 密钥与 SMTP 邮箱配置全部走环境变量（见下表）、HikariCP 最大连接数 50、开启 SSL（`useSSL=true`）、日志收敛为 info/warn |
| `logback-spring.xml` | 日志配置 |

`application-prod.yml` 已内置，无需新增；如需其他环境（如 test），仿照 `application-prod.yml` 新增 `application-{env}.yml` 并以 `--spring.profiles.active={env}` 启动。

## 4. 环境变量 / 外部化配置清单

生产环境敏感信息一律通过环境变量注入（`application-prod.yml` 以 `${...}` 占位）：

| 环境变量 | 含义 | 默认值（prod） | 是否必须 |
| --- | --- | --- | --- |
| `DB_HOST` | MySQL 主机 | `localhost` | 建议设置 |
| `DB_PORT` | MySQL 端口 | `3306` | 建议设置 |
| `DB_NAME` | 数据库名 | `ytt_db` | 建议设置 |
| `DB_USER` | 数据库账号 | `root` | 建议设置（生产请用专用账号） |
| `DB_PASSWORD` | 数据库密码 | 空 | **必须设置** |
| `JWT_SECRET` | JWT 签名密钥 | 无 | **必须设置** |
| `MAIL_HOST` | SMTP 服务器主机 | `smtp.qq.com` | 使用验证码登录时必须正确 |
| `MAIL_PORT` | SMTP 端口（SSL） | `465` | 同上 |
| `MAIL_USERNAME` | 发件邮箱账号（完整邮箱地址） | 空 | **必须设置**（否则无法发信） |
| `MAIL_PASSWORD` | SMTP 授权码（非邮箱登录密码） | 空 | **必须设置**（QQ 邮箱在「设置→账号→POP3/SMTP 服务」中生成） |

> 如不启用邮箱验证码登录，可将 `MAIL_USERNAME`/`MAIL_PASSWORD` 留空；此时调用验证码发送接口将返回 `50002 邮件发送失败`，不影响密码登录。

关于 JWT 配置（`application.yml` 的 `jwt.*`）：

- `jwt.secret`：公共配置中仅为开发用默认值，**生产必须通过 `JWT_SECRET` 覆盖**（`application-prod.yml` 中 `jwt.secret: ${JWT_SECRET}`，未设置将无法启动）。
- `jwt.access-expire: 7200`：访问令牌有效期（秒），即 2 小时；过期后前端应调用 `/auth/refresh` 换新。
- `jwt.refresh-expire: 604800`：刷新令牌有效期（秒），即 7 天；超过后需重新登录。
- `jwt.header: Authorization`、`jwt.prefix: "Bearer "`：令牌传递方式。

## 5. 数据库准备与自动迁移

1. 仅需要手工创建空库（MySQL 5.7+，**必须 utf8mb4**）：

   ```sql
   CREATE DATABASE ytt_db DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
   ```

2. 后端启动时 Flyway 自动执行 `classpath:db/migration` 下的迁移（`baseline-on-migrate: true`，各环境均已开启）：
   - `V1__init.sql`：建表（用户/角色/权限/题目/分类/错题/考试记录/学习计划等）；
   - `V2__seed.sql`：种子数据（内置角色 ADMIN/STUDENT、后台权限点、题目分类、41 道内置题库）；
   - `V3__add_email.sql`：`sys_user` 增加 `email` 非空唯一列，并按 `{username}@yantitong.local` 回填存量账号。

3. 迁移完成后，启动初始化器 `DataInitializer` 自动创建内置账号（已存在则跳过）：`admin/123456`（管理员）、`study/123456`（学员）。**生产部署后请立即登录修改这两个账号的密码或予以禁用。**

## 6. Nginx 参考配置

前端 `dist` 静态托管 + `/api/` 反向代理到后端 `127.0.0.1:8080`：

```nginx
server {
    listen       80;
    server_name  your-domain.example.com;

    # 前端静态资源
    root   /opt/ytt/dist;
    index  index.html;

    # 单页应用路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 后端接口反向代理（后端 context-path 为 /api，路径无需改写）
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        # 后端限流与登录 IP 记录优先取 X-Forwarded-For
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # 上传体积与后端一致（后端限制：单文件 5MB / 请求 10MB）
    client_max_body_size 10m;
}
```

## 7. 常见问题

| 问题 | 说明 |
| --- | --- |
| 跨域（CORS） | 后端已通过 `CorsFilter` 全局放开跨域，前后端分端口/分域部署无需额外处理；生产收敛域名白名单可在该过滤器中调整 |
| MySQL 5.7 字符集 | 必须使用 `utf8mb4` 建库，否则 Emoji 与部分汉字会报错或截断；连接串已带 `useUnicode=true&characterEncoding=UTF-8` |
| 驱动兼容性 | 项目使用 MySQL Connector/J 8.0.33，向下兼容 MySQL 5.7 服务端；Flyway 7.15 社区版支持 MySQL 5.7 |
| Token 注销黑名单 | `TokenBlacklist` 为内存实现（`ConcurrentHashMap`）：**服务重启后黑名单失效**（已注销 Token 在过期前可能恢复可用）；集群部署时各实例不共享黑名单，需替换为 Redis 等分布式实现 |
| 邮箱验证码存储 | 验证码（6 位数字、5 分钟有效、60 秒防刷）保存在**服务端内存**（`ConcurrentHashMap`），不落库、不落日志明文：服务重启后未使用的验证码全部失效；集群多实例间不共享，用户请求落到不同实例会校验失败，生产集群需替换为 Redis（key 建议 `email-code:{purpose}:{email}`，TTL 300 秒） |
| SMTP 授权码 | 授权码等同于发信密码，**严禁写入代码仓库**：dev/prod 配置均不含明文，统一通过 `MAIL_USERNAME`/`MAIL_PASSWORD` 环境变量或配置中心注入（dev 未设置时应用可正常启动，仅发信返回 50002）；授权码泄露后应立即在邮箱设置中作废重生成 |
| 接口限流 | 同为内存实现（按 IP），集群部署需替换为 Redis 分布式限流；额度见 `application.yml` 的 `rate-limit.*` |
| 默认账号安全 | 演示账号以**用户名**登录：`admin/123456`（管理员）、`study/123456`（学员）；邮箱 `admin@yantitong.local`、`study@yantitong.local` 仅用于邮箱验证码免密登录。生产上线后第一时间修改密码 |
| 接口文档暴露 | `/api/swagger-ui.html` 默认公开可访问，生产环境建议通过 Nginx 或 Security 配置限制 `/swagger-ui/**`、`/v3/api-docs/**` 的访问 |

## 8. 认证安全说明（HTTPS / CSRF / 邮箱登录 / Token 过期）

| 主题 | 现状与生产要求 |
| --- | --- |
| HTTPS 传输加密 | 开发环境走 HTTP 仅用于本机联调；**生产环境必须全站 HTTPS**：Nginx 配置 443 监听 TLS 证书并将 80 端口 301 跳转至 443；后端 MySQL 连接在 `application-prod.yml` 已强制 `useSSL=true`；JWT、密码等敏感数据全程在 TLS 隧道内传输。 |
| CSRF 防护（架构性豁免） | 系统采用**无状态认证**：令牌经 `Authorization: Bearer <token>` 请求头传递，服务端不使用 Cookie 维持会话、不存在会话 Cookie。CSRF 的前提是浏览器自动携带站点凭证（Cookie）发起跨站请求，而自定义 Authorization 头不会被跨站页面自动附加（跨域请求还受 CORS 白名单约束），故该架构下 **CSRF 不适用**，`SecurityConfig` 中显式关闭 CSRF 属于合理设计；如未来改为 Cookie 方式存证，则必须重新启用 CSRF Token 防护。 |
| 登录凭证（双轨） | 系统提供两种登录方式：① **用户名 + 密码**——密码登录按用户名（唯一标识）查询账号，用户不存在返回 `40401 用户不存在`，密码错误返回 `40104`，禁用账号返回 `40105`；② **邮箱验证码登录**——按邮箱查询账号（不存在返回 `40401`）。注册仍要求填写邮箱：前后端双重格式校验（`@Email`）、数据库 `uk_sys_user_email` 唯一约束兜底（email 冲突返回 40905）。 |
| 邮箱验证码 | 已实现**邮箱验证码登录**（模拟短信验证码流程）：`POST /auth/email/code` 按邮箱查用户（不存在返回 `40401`），生成 6 位随机数字验证码（`SecureRandom`，保留前导零），经 SMTP（QQ 邮箱 SSL 465）发送 HTML 中文邮件，**有效期 5 分钟**、同一邮箱 **60 秒内禁止重发**（`42901`）；`POST /auth/email/login` 校验——验证码错误返回 `40106`、过期/未发送返回 `40107`，成功后签发双 Token 并**立即销毁验证码（一次性消费）**。验证码存于内存、不落日志，生产集群需替换为 Redis；SMTP 主机/账号/授权码全部通过 `MAIL_*` 环境变量注入。 |
| 密码安全 | 密码统一使用 **BCrypt** 加盐哈希存储，任何场景不返回、不落日志；登录失败统一模糊提示"用户名或密码错误"，避免账号探测。 |
| 登录限流 | `POST /auth/login` 限制 **5 次/分钟/IP**（注册、发送验证码各 10 次/分钟），超限返回 `42900`；验证码另设 60 秒业务级防刷（`42901`）；均为单机内存实现，集群部署需替换为 Redis 分布式限流。 |
| Token 过期处理 | access token 有效期 2 小时、refresh token 7 天。前端三重保障：① 启动/路由守卫本地解析 `exp`，过期即清理会话并跳登录页；② 定时器在到期前 1 分钟预警、到期自动登出；③ 请求返回 `40102` 时自动用 refresh token 无感刷新并重放，刷新失败/令牌无效（`40100/40101/40103/40105`）则弹错误通知并强制登出，会话数据（内存态、定时器、全部 `ytt_` 前缀本地存储）一并清理。 |
| 黑名单 | 注销、改密、refresh 旋转后的旧 Token 立即入黑名单（`40103`）；为单机内存实现，重启或多实例场景需替换为 Redis。 |

Nginx HTTPS 参考（在第 6 节配置基础上增加）：

```nginx
# 80 全部跳转 HTTPS
server {
    listen 80;
    server_name your-domain.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name your-domain.example.com;

    ssl_certificate     /etc/nginx/cert/your-domain.pem;
    ssl_certificate_key /etc/nginx/cert/your-domain.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    root /opt/ytt/dist;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
    client_max_body_size 10m;
}
```
